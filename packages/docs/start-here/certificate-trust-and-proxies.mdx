---
title: "Certificate trust and proxies"
description: "Configure private CAs and outbound proxies for AgencyAI Desktop and its local runtimes."
---

AgencyAI Desktop has two relevant network trust surfaces. Installing a private
root for one surface does not automatically configure the other.

## Desktop HTTPS

External HTTPS calls from the desktop use Electron's Chromium network stack.
That path uses Chromium/Electron certificate trust and the system proxy
configuration. The built-in browser panel has its own explicit proxy surface
for browsing traffic.

Install enterprise roots in OS trust on Windows and macOS. On Linux, also
import the root into the Chromium/Electron-compatible NSS or user trust
database required by the distribution. Do not assume `/etc/ssl` alone is
sufficient for Electron on every Linux image.

Bare Node `fetch` is not the sanctioned desktop external path. Desktop network
calls route through `electronNet.fetch`, but that does not remove the Linux
Chromium/NSS trust-store distinction.

## Spawned local runtimes and sidecars

The desktop starts local runtimes and sidecars. For Node-compatible child
processes, AgencyAI can generate a `system-ca-bundle.pem` inside the user data
directory and pass it with `NODE_EXTRA_CA_CERTS`.

- A user-provided `NODE_EXTRA_CA_CERTS` value always wins.
- The generated bundle does not configure Electron's Chromium trust store.
- Proxy environment-variable support varies by runtime and sidecar; use the
  settings documented for that component.

Example process-level proxy configuration:

```dotenv
NODE_USE_ENV_PROXY=1
HTTPS_PROXY=http://proxy.example.internal:8080
NO_PROXY=localhost,127.0.0.1
```

These are process-start settings. Changing them in a browser tab or after a
runtime starts is too late.

## Validate the setup

- Use the PowerShell doctor in [Network diagnostics](/start-here/network-diagnostics)
  for Windows reachability and TLS-chain evidence.
- Use [Outbound network access](/start-here/outbound-network-access) to identify
  the endpoints required by configured model providers and tools.
- Test Electron and the spawned runtime separately; a successful `curl` check
  does not prove that Chromium trusts the same private root.
